## 각 단계 작업 범위

### 1단계 — 가상 데이터 기반 4개 화면
- 서버 연결 없음, 앱을 다시 열면 예시 데이터로 초기화(정상 동작)
- 상세 작업은 아래 **J장**

### 2단계 — 계정·기록 저장·복약 알림
1. Supabase 프로젝트 생성(서울 리전, 무료) — **가상 데이터만 사용**
2. SQL 마이그레이션 파일로 테이블·RLS·트리거 작성 (`supabase/migrations/`) — 🔒 별도 검토
3. 로그인(이메일 숫자코드 → 승인 시 카카오), 세션 암호화 저장
4. 동의 화면 → `consents` 저장
5. 1단계 데이터 층(`src/data`)의 구현만 Supabase로 교체 — **화면 코드는 원칙적으로 수정 없음**
6. 로컬 복약 알림: 일정 저장 시 기기 알림 예약, 수정·삭제 시 재예약. 안드로이드 정확한 시각 권한 처리 방침 결정
7. 계정 삭제 Edge Function 1개 — 🔒 별도 검토
8. 단위 테스트 도입(jest-expo, 승인 후 설치): 입력 검증·날짜 계산·통계 계산 함수

### 3단계 — 가족 공유·건강 통계
1. 초대 코드 생성·검증 서버 함수 (해시 저장, 24시간 만료, 5회 실패 폐기) — 🔒
2. 제3자 제공 동의 화면 + `family_links` 생성 — 🔒
3. `get_shared_summary` 등 가족 조회 함수 (권한 재검사 + 감사기록) — 🔒
4. 공유 항목 변경·철회(양쪽 모두)
5. 7일·30일 평균·최저·최고·기록일수 + 단순 막대
6. RLS·서버 함수 자동 테스트 (SQL 테스트 스크립트: "남의 기록 읽기 시도 → 실패" 등)

### 4단계 — 보안 검증·사용자 테스트·배포 준비
1. 보안 점검표 수행 (아래 I-4)
2. 어르신 사용자 테스트 5~8명 (50대·60대·70대 이상 각 2명 이상, 아이폰·안드로이드 혼합), 가상 데이터 사용
3. **전문가 검토**: 개인정보(민감정보 동의, 제3자 제공, 국외이전·위탁), 디지털의료·건강지원기기 해당 여부, 스토어 문구
4. 개인정보 처리방침·이용약관 확정, 웹페이지 게시(GitHub Pages)
5. Supabase Pro 전환(승인 후), 백업 확인
6. 스토어 등록 자료: 아이콘, 스크린샷(예시 데이터), 설명문, 개인정보 라벨(Apple)·데이터 보안 양식(Google)
7. 내부 테스트 배포(TestFlight / Play 내부 테스트) → **정식 제출은 별도 승인**

## I. 단계별 검수 기준

### I-0. 모든 단계 공통
- [ ] TypeScript 타입 검사 오류 0개
- [ ] 아이폰·안드로이드 실제 기기 각 1대에서 동작 확인
- [ ] 본문 18~20pt, 중요한 숫자 26pt 이상, 버튼 높이 52dp 이상
- [ ] 휴대폰 글씨 크기 최대에서 글자 잘림·겹침 없음
- [ ] VoiceOver/TalkBack이 모든 버튼·숫자를 한국어로 읽음
- [ ] 상태가 색 없이도(글자·아이콘으로) 구분됨
- [ ] 진단·판정·처방·약 변경 지시 문구 없음 (문구 전체 검색으로 확인)
- [ ] 새로 설치한 패키지 목록과 이유 보고 (승인 없는 설치 0개)
- [ ] 변경 파일 목록·테스트 결과 보고서 제출

- [ ] 혈압·혈당·체중 입력 → 목록·오늘 화면에 즉시 반영 (메모리)
- [ ] 기록 수정·삭제(확인창 포함) 동작
- [ ] 약 추가·수정·복약시간 설정 화면 동작 (알림은 아직 없음)

### J-4. 폴더 구조 (예정)

> 실제 구현에서는 SDK 58 템플릿에 맞춰 화면 폴더가 `src/app/`가 되었고, 혈압·혈당·체중 입력은 `record/new.tsx` 하나로 합쳤습니다. 달라진 점 전체는 PHASE1_REPORT.md 4장 참고.

```
/
├─ CLAUDE.md
├─ docs/  (MASTER_PLAN.md, FEATURES.md, ROADMAP.md)
├─ app/                         ← 화면 (Expo Router: 파일 = 화면 주소)
│  ├─ _layout.tsx               ← 전체 틀 + 데이터 공급(Provider)
│  ├─ (tabs)/
│  │  ├─ _layout.tsx            ← 하단 탭 4개
│  │  ├─ index.tsx              ← ① 오늘
│  │  ├─ records.tsx            ← ② 건강기록
│  │  ├─ meds.tsx               ← ③ 약·병원
│  │  └─ family.tsx             ← ④ 가족 안심
│  ├─ record/
```

### J-5. 공통 부품 규칙 (상세)

| 부품 | 규칙 |
|---|---|
| AppText | 종류: `title`(24pt) / `body`(19pt) / `caption`(17pt, 최소) / `number`(32pt, 굵게). 휴대폰 글씨 확대 반영, 최대 배율 제한(레이아웃 보호 값은 실기기로 결정) |
| AppButton | 높이 56dp, 글자 19pt+, `label` 필수(아이콘만 금지), `accessibilityLabel`·`accessibilityRole="button"` 자동, 누름 상태는 테두리·배경 변화(애니메이션 없음) |
| NumberField | `keyboardType="number-pad"`, 글자 32pt, 단위 표시(mmHg 대신 쉬운 표기 검토), 범위 밖 입력 시 "숫자를 다시 확인해 주세요" |
| StatusMark | 아이콘 + 글자 항상 함께. 스크린리더용 문장 제공("저녁 약, 아직 안 드셨어요") |
| SampleBadge | `source === 'sample'`이면 자동 표시 |

### J-6. 예시 데이터 (가상)
- 가상 사용자 "김예시(72세 가정)" — 실제 인물 아님
- 혈압 14일치(하루 1~2회), 혈당 14일치, 체중 주 2회
- 약 3개: "혈압약(예시)" 아침, "당뇨약(예시)" 아침·저녁, "영양제(예시)" 점심
- 병원 일정 2개: 오늘 오후 2시 "예시내과", 다음 주 "예시정형외과"(질문 메모 2개)
- 가족 2명(예시): 딸(혈압·약 공유), 아들(약만 공유) / 긴급 연락처 1명
- 값은 무작위가 아닌 고정값 사용 (화면 확인·테스트 재현을 위해)

### J-7. 테스트 방법 (1단계)
1. `npx tsc --noEmit` — 타입 오류 0개
2. `npx expo start` → 아이폰·안드로이드 Expo Go로 QR 스캔하여 실행
3. I-1 검수표를 기기별로 체크 (스크린샷 첨부)
4. 휴대폰 설정에서 글씨 크기 최대 → 4개 탭·입력 화면 확인
5. VoiceOver(아이폰) / TalkBack(안드로이드)으로 오늘 화면 조작
6. 금지 문구 검색
7. (가능하면) 주변 50대 이상 1~2명 간이 테스트: "저녁 약 먹은 걸 표시해 보세요", "혈압 128 / 82를 기록해 보세요"

> 단위 테스트 도구(jest-expo)는 설치가 필요하므로 1단계에서는 도입하지 않고, 2단계에서 승인 후 도입한다.

### J-8. 1단계 완료 보고 형식
1. 한 일 요약 (3~5줄)
2. 생성·변경한 파일 목록
3. 설치된 패키지 (템플릿 기본 외 추가분: 0개 목표)
4. 검수표 결과 (통과 / 미통과 + 이유)
5. 스크린샷 (4개 탭 + 입력 화면)
6. 알려진 문제·2단계로 넘길 일
7. 2단계 진행을 위해 사용자가 결정할 사항
