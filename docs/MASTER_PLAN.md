## 0. 한 줄 요약

> **"약 먹었는지 확인하고, 혈압·혈당 숫자를 적는다" — 이 두 가지를 50~80대가 설명 없이 할 수 있게 만드는 것이 이 앱의 전부다.**
> 나머지 기능(통계, 가족 공유, 병원 일정)은 이 두 가지를 돕는 보조 기능이다.

### 핵심 설계 결정 (요약)

| 결정 | 선택 | 이유 |
|---|---|---|
| 앱 개발 방식 | Expo + React Native + TypeScript | 한 번 작성으로 아이폰·안드로이드 동시 지원, 무료 |
| 화면 이동 | Expo Router (기본 포함) | 별도 설치 없이 탭 4개 구성 가능 |
| 서버·DB | Supabase (PostgreSQL) | 인증·DB·접근권한(RLS)을 한 곳에서 해결, 별도 서버 불필요 |
| 복약 알림 | **기기 안 알림(로컬 알림)** 만 사용 | 푸시 서버 불필요 → 비용 0원, 인터넷 없어도 알림 동작 |
| 가족 공유 | 서버 함수(RPC)로만 조회 + 서버에서 권한 검사 | "앱에서만 막는" 방식은 위험. 서버가 최종 문지기 |
| 통계 그래프 | 별도 차트 라이브러리 없이 기본 도형으로 단순 막대 표시 | 패키지 최소화, 어르신에게는 단순한 표가 더 읽기 쉬움 |
| 상태 관리 | React 기본 기능(Context + useReducer) | 추가 라이브러리 불필요 |
| AI·OCR·외부 유료 API | **사용하지 않음** | 비용·규제 위험 회피 |

## A. 전체 시스템 구조도

```
┌──────────────────────────── 사용자 휴대폰 (아이폰 / 안드로이드) ────────────────────────────┐
│                                                                                           │
│   오늘건강 앱 (Expo + React Native + TypeScript)                                            │
│   ┌─────────────────────────────────────────────────────────────────────────────────────┐ │
│   │ 화면 층 (Expo Router)                                                                │ │
│   │   [① 오늘]   [② 건강기록]   [③ 약·병원]   [④ 가족 안심]      ← 하단 탭 4개 고정     │ │
│   │   + 입력 화면(혈압·혈당·체중·약·일정) / 동의 화면 / 로그인 화면                     │ │
│   ├─────────────────────────────────────────────────────────────────────────────────────┤ │
│   │ 공통 부품 층 (src/components/ui)                                                     │ │
│   │   큰글씨 텍스트 · 큰 버튼 · 숫자 입력창 · 카드 · 상태표시(아이콘+글자) · '예시' 표시   │ │
│   ├─────────────────────────────────────────────────────────────────────────────────────┤ │
│   │ 데이터 층 (src/data)                                                                 │ │
│   │   1단계: 예시 데이터(메모리)   →   2단계 이후: Supabase 연결                           │ │
│   │   ※ 화면은 같은 함수만 부름. 데이터 출처만 교체 (화면 코드 재작성 불필요)             │ │
│   ├─────────────────────────────────────────────────────────────────────────────────────┤ │
│   │ 기기 기능 (추가 서버 없음)                                                           │ │
│   │   로컬 알림(expo-notifications) · 전화 걸기(119/가족, 기본 Linking) · 공유창(Share)   │ │
│   │   로그인 정보 보관(암호화 저장소)                                                     │ │
│   └─────────────────────────────────────────────────────────────────────────────────────┘ │
└───────────────────────────────────────────┬───────────────────────────────────────────────┘
                                            │  HTTPS (TLS 암호화 전송)
                                            ▼
┌──────────────────────────── Supabase (서울 리전, ap-northeast-2) ─────────────────────────┐
│   인증(Auth)          : 로그인, 세션, 계정                                                  │
│   PostgreSQL DB       : 건강기록·약·일정·가족연결·동의·감사기록 (저장 시 디스크 암호화)       │
│   RLS(행 단위 보안)   : "내 기록은 나만" — 모든 테이블에 적용                                │
│   RPC(DB 함수)        : 가족 조회는 이 함수로만 → 연결·동의·항목 권한 검사 + 감사기록 남김    │
│   트리거              : 기록 생성·수정·삭제 시 감사기록 자동 작성                            │
│   Edge Function 1개   : 계정 완전 삭제 (관리자 권한이 필요한 유일한 작업)                    │
└───────────────────────────────────────────────────────────────────────────────────────────┘

┌──────────── 개발·배포 도구 (운영 서버 아님) ────────────┐
│ GitHub: 코드 보관·변경 이력                              │
│ EAS Build(무료 등급): 앱 설치 파일 제작                  │
│ App Store Connect / Google Play Console: 스토어 제출     │
└─────────────────────────────────────────────────────────┘

만들지 않는 것: 별도 API 서버, 관리자 웹페이지, AI 분석 서버, 푸시 발송 서버, 유료 문자(SMS) 연동
```

### 데이터가 흐르는 길 (예: 혈압 기록)
1. 사용자가 [혈압 기록하기] → 숫자 3개 입력 → [저장]
2. 앱이 입력값이 숫자로서 가능한 범위인지 확인 (예: 수축기 50~260). **건강 판정은 하지 않음**
3. HTTPS로 Supabase에 저장 요청 → RLS가 "본인 데이터인지" 검사 → 저장
4. 트리거가 감사기록(누가·언제·무엇을) 자동 작성
5. 화면에 "저장했어요" + [되돌리기] 표시

## C. 화면별 사용 흐름

### C-0. 전체 화면 지도

```
[처음 실행]
   └─ 시작 안내(1장) → 로그인(카카오/이메일) → 동의 화면(필수 3 + 선택 0) → 글씨 크기 확인 → [① 오늘]

[하단 탭 4개] ─────────────────────────────────────────────────────────────
 ① 오늘            ② 건강기록            ③ 약·병원              ④ 가족 안심
  ├ 약 확인         ├ 혈압 목록·입력      ├ 내 약 목록           ├ 긴급 전화(119/가족)
  ├ 혈압 입력       ├ 혈당 목록·입력      │  └ 약 추가·수정       ├ 가족 목록
  ├ 혈당 입력       ├ 체중 목록·입력      │     └ 복약시간 설정    │  └ 가족별 공유 항목 설정
  ├ 오늘 진료       ├ 7일/30일 요약       ├ 병원 일정 목록       │     └ 공유 중단(철회)
  └ 완료 현황       └ 기록 수정·삭제      │  └ 일정 추가·수정     ├ 가족 초대(코드)
                                           │     └ 질문 메모       ├ 받은 초대 수락
                                           └ 알림 설정             └ 가족이 공유한 정보 보기
[설정] (각 탭 오른쪽 위 톱니 아이콘 + '설정' 글자)
  글씨 크기 · 알림 · 동의 내역 · 내 정보 내려받기(4단계) · 계정 삭제 · 로그아웃
```

### C-1. ① 오늘 — 하루 사용 흐름 (가장 중요)

```
앱 열기
 │
 ▼
┌───────────────────────────────┐
│ 11월 4일 수요일                │  ← 날짜 크게 (26pt+)
│ 오늘 할 일 4개 중 2개 했어요   │  ← 글자 + ✓ 아이콘 (색만으로 구분 안 함)
├───────────────────────────────┤
│ 💊 아침 약   ✓ 먹었어요 08:12  │
│ 💊 저녁 약   [ 먹었어요 ]      │  ← 52dp 이상 큰 버튼, 한 번 누르면 완료
├───────────────────────────────┤
│ [ 혈압 기록하기 ]              │  ← 오늘 기록 있으면 "오늘 혈압 128/82" 표시
│ [ 혈당 기록하기 ]              │
├───────────────────────────────┤
│ 🏥 오늘 진료: 오후 2시 내과    │  ← 일정 없으면 이 칸 숨김
└───────────────────────────────┘
```

- **약 확인**: [먹었어요] 1번 터치 → 즉시 "먹었어요 08:12"로 바뀜 + 5초간 [취소] 표시. 실수로 눌러도 되돌릴 수 있음.
- **혈압 입력**: [혈압 기록하기] → 입력 화면(위 숫자 / 아래 숫자 / 맥박) → 숫자 키패드 자동 표시 → [저장] → "저장했어요" → 오늘 화면으로 복귀.
  - 측정 시각은 "지금"이 기본값, 바꾸고 싶을 때만 [시간 바꾸기].
  - 불가능한 숫자(예: 위 숫자 400)는 "숫자를 다시 확인해 주세요"만 안내. **"높아요/위험해요" 같은 판정 문구 없음.**
- **혈당 입력**: 숫자 1개 + 언제 쟀는지 버튼 4개 중 선택(공복 / 식사 후 / 자기 전 / 기타).
- 화면당 핵심 행동: 약 확인, 혈압 기록, 혈당 기록 = 3개.

### C-2. ② 건강기록

```
[혈압] [혈당] [체중]   ← 큰 글씨 선택 버튼 (현재 선택은 굵은 테두리 + '선택됨' 읽기)
[최근 7일] [최근 30일]
┌───────────────────────────────┐
│ 7일 평균  위 129 / 아래 83     │  ← 단순 평균만. 판정 없음
│ 기록한 날 6일 / 7일            │
│ ▁▃▅▃▂▄▃ (단순 막대)            │  ← 선택: 보조 표시. 표가 기본
├───────────────────────────────┤
│ 11/4(수) 08:10  128 / 82  맥박 72 │ → 누르면 수정·삭제 화면
│ 11/3(화) 07:55  131 / 85  맥박 70 │
└───────────────────────────────┘
[ + 새로 기록하기 ]
```

- 삭제: [삭제] → "이 기록을 지울까요?" 확인창 → [지우기] / [그만두기] (2단계 확인).
- 예시 데이터는 각 줄에 **'예시'** 글자 표시.

### C-3. ③ 약·병원

- **약 등록**: [약 추가] → ① 약 이름(직접 입력) → ② 한 번에 얼마나(예: "1알", 자유 입력) → ③ 언제 드세요? (아침/점심/저녁/자기 전 버튼 + 시각 조정) → ④ [저장] → "매일 8시에 알려드릴게요" 확인.
  - **약 이름 검색·약품 DB 연동은 하지 않음** (외부 API·정확성 책임 문제). 직접 입력.
  - 용량·횟수에 대해 앱이 조언하지 않음.
- **복약 알림**: 정해진 시각에 기기 알림 "저녁 약 드실 시간이에요" → 알림 누르면 [오늘] 화면의 해당 약으로 이동 → [먹었어요].
- **병원 일정**: [일정 추가] → 병원 이름 / 과(선택) / 날짜·시각 → [저장]. 전날·당일 알림(선택).
- **질문 메모**: 일정 안에 "의사 선생님께 물어볼 것" 목록. 진료 후 체크.

### C-4. ④ 가족 안심

```
┌───────────────────────────────┐
│ [ 📞 119 전화하기 ]            │  ← 맨 위, 가장 큰 버튼
│ [ 📞 딸 김영희에게 전화 ]       │  ← 긴급 연락처 1순위
├───────────────────────────────┤
│ 내 정보를 보는 가족            │
│  김영희(딸) · 혈압, 약 확인 공유 │ → [공유 항목 바꾸기] [공유 그만두기]
│ [ + 가족 초대하기 ]             │
├───────────────────────────────┤
│ 내가 보는 가족                 │
│  어머니 · 오늘 약 2/3 확인      │ → 공유된 항목만 보기
│ [ 초대 코드 입력하기 ]          │
└───────────────────────────────┘
```

- **119 전화**: 누르면 "119에 전화할까요?" 확인창 → [전화 걸기] → 휴대폰 전화 앱이 열림. **앱이 자동으로 신고하지 않음.**
- **가족 초대**(공유하는 사람 = 본인):
  1. [가족 초대하기] → 관계 입력(딸, 아들 등)
  2. 공유할 항목 고르기: 혈압 / 혈당 / 체중 / 약 확인 여부 / 병원 일정 (기본값 모두 꺼짐 = 최소 공유)
  3. **제3자 제공 동의 화면**: 누구에게(가족), 무엇을(선택 항목), 왜(안부 확인), 언제까지(철회 시까지), 거부할 수 있음 — 확인 후 [동의하고 초대 코드 만들기]
  4. 6자리 코드 생성(24시간 유효) → [카톡으로 보내기] (휴대폰 기본 공유창 사용, 별도 카카오 연동 없음)
- **초대 수락**(가족 쪽): [초대 코드 입력하기] → 코드 6자리 → "어머니가 혈압·약 확인을 공유합니다. 받으시겠어요?" → [받기]
- **동의 철회**: [공유 그만두기] → 확인창 → 즉시 서버에서 차단. 가족 화면에서 바로 사라짐.

### C-5. 처음 실행 · 동의 흐름

1. 시작 안내 1장: "약 확인과 혈압·혈당 기록을 도와드려요. 병을 진단하거나 약을 바꾸라고 하지 않아요."
2. 로그인
3. 동의 화면 (항목별 개별 체크, '전체 동의' 버튼 있지만 각 항목 내용 펼쳐보기 가능)
   - [필수] 서비스 이용약관
   - [필수] 개인정보 수집·이용
   - [필수] **건강정보(민감정보) 처리 — 별도 동의** (혈압·혈당·체중·복약기록)
   - [확인] 만 14세 이상입니다
   - 가족 공유 동의는 여기서 받지 않음 → 실제로 가족을 초대할 때 따로 받음
4. 알림 권한 요청 — **권한 요청 전에 "왜 필요한지" 화면 먼저 표시** (앱 접근권한 고지)
5. 글씨 크기 확인: "이 글씨가 잘 보이세요?" [잘 보여요] [더 크게]

## D. 데이터베이스 테이블 설계안

### D-0. 공통 원칙
- 모든 테이블에 RLS(행 단위 보안) **켜기**. 정책 없는 테이블은 아무도 접근 못함(기본 차단).
- 모든 기록에 `user_id`(주인), `created_at`, `updated_at`.
- 건강·복약 기록에 `source` 컬럼: `'real'`(실제) / `'sample'`(예시) → **실제와 예시를 항상 구분**.
- 가족은 테이블을 직접 읽을 수 **없음**. 오직 `get_shared_*` 서버 함수를 통해서만, 함수 안에서 "연결 상태 + 동의 + 항목 권한"을 검사.
- 수집 최소화: 생년월일·성별·주소·주민번호·질병명 **수집하지 않음**. (질병명은 필요성 재검토 후 2차 이후 판단)
- 삭제: 사용자가 지운 기록은 실제 삭제(hard delete). 계정 삭제 시 모든 기록 연쇄 삭제(cascade). 감사기록만 법정 보관기간 동안 개인 식별값을 분리해 보관 [전문가 검토].

### D-1. 테이블 목록과 권한

> 표기: 본인 = 기록 주인, 가족 = 공유 동의를 받은 가족, 시스템 = 서버 함수·트리거

| # | 테이블 | 구분 | 생성 | 조회 | 수정 | 삭제 |
|---|---|---|---|---|---|---|
| 1 | `profiles` | 사용자 정보 | 시스템(가입 시) | 본인 | 본인 | 시스템(계정 삭제) |
| 2 | `consents` | 동의 기록 | 본인 | 본인 | ✕ (철회는 새 행·`withdrawn_at` 기록) | ✕ (증빙 보관) |
| 3 | `health_measurements` | 건강 측정 기록 | 본인 | 본인 / 가족(서버함수·허용 항목만) | 본인 | 본인 |
| 4 | `medications` | 등록 약품 | 본인 | 본인 | 본인 | 본인 |
| 5 | `medication_schedules` | 복약 일정 | 본인 | 본인 | 본인 | 본인 |
| 6 | `medication_intakes` | 복약 확인 기록 | 본인 | 본인 / 가족(서버함수·'약 확인' 허용 시 여부만) | 본인 | 본인 |
| 7 | `appointments` | 병원 방문 일정 | 본인 | 본인 / 가족(서버함수·허용 시) | 본인 | 본인 |
| 8 | `appointment_questions` | 진료 질문 메모 | 본인 | 본인 **만** (가족 공유 안 함) | 본인 | 본인 |
| 9 | `family_invites` | 가족 초대 코드 | 본인 | 본인 | ✕ | 본인(취소) |
| 10 | `family_links` | 가족 연결·공유 항목 | 시스템(코드 수락 함수) | 본인·해당 가족 | 본인(공유 항목·철회) | ✕ (철회 상태로 남김) |
| 11 | `emergency_contacts` | 긴급 연락처 | 본인 | 본인 | 본인 | 본인 |
| 12 | `notification_settings` | 알림 설정 | 본인 | 본인 | 본인 | 시스템 |
| 13 | `audit_logs` | 보안 감사 기록 | **시스템만** | 본인(내 정보 관련 기록만) | ✕ 누구도 불가 | ✕ (보관기간 후 시스템 정리) |

### D-2. 테이블 상세

```sql
-- 설계안(초안). 실제 SQL은 2단계에서 작성·검토
-- 1. 사용자 정보 (Supabase auth.users 와 1:1)
profiles (
  id              uuid PK  = auth.users.id
  display_name    text      -- 호칭 (예: "김순자"), 실명 강제 안 함
  font_scale      numeric   default 1.0   -- 글씨 배율 1.0~1.6
  created_at, updated_at
)

-- 2. 동의 기록 (버전 관리, 철회 이력 보존)
consents (
  id              uuid PK
  user_id         uuid FK → profiles
  consent_type    text  check in ('terms','privacy','sensitive_health','age_14')
  version         text      -- 약관 버전 (예: '2027-01-v1')
  agreed_at       timestamptz
  withdrawn_at    timestamptz null
)

-- 3. 건강 측정 기록 (혈압·혈당·체중을 한 테이블에, 종류별 검사 규칙)
health_measurements (
  id              uuid PK
  user_id         uuid FK
  kind            text  check in ('bp','glucose','weight')
  systolic        int   null  -- 혈압 위 숫자  (bp일 때 필수, 50~260)
  diastolic       int   null  -- 혈압 아래 숫자 (bp일 때 필수, 30~160)
  pulse           int   null  -- 맥박 (선택, 30~220)
  glucose_mgdl    int   null  -- 혈당 (glucose일 때 필수, 20~600)
  glucose_timing  text  null  check in ('fasting','after_meal','bedtime','other')
  weight_kg       numeric(5,1) null  -- 체중 (weight일 때 필수, 20~250)
  measured_at     timestamptz
  memo            text  null (최대 200자)
  source          text  check in ('real','sample') default 'real'
  created_at, updated_at
)
-- ※ 숫자 범위는 "입력 실수 방지"용이지 건강 판정 기준이 아님

-- 4. 등록 약품
medications (
  id, user_id
  name            text      -- 사용자가 직접 입력 (외부 약품 DB 연동 없음)
  dose_text       text null -- "1알", "반 알" 등 자유 입력
  memo            text null
  is_active       boolean default true   -- 그만 먹는 약은 숨김(기록 보존)
  source, created_at, updated_at
)

-- 5. 복약 일정
medication_schedules (
  id, user_id
  medication_id   uuid FK → medications (cascade)
  slot            text check in ('morning','noon','evening','bedtime','custom')
  time_of_day     time      -- 예: 08:00
  days_of_week    smallint[] default {0..6}   -- 매일 기본
  remind          boolean default true
  created_at, updated_at
)

-- 6. 복약 확인 기록
medication_intakes (
  id, user_id
  schedule_id     uuid FK → medication_schedules (cascade)
  scheduled_date  date
  status          text check in ('taken','skipped')
  checked_at      timestamptz
  source, created_at, updated_at
  UNIQUE (schedule_id, scheduled_date)   -- 같은 날 중복 확인 방지
)

-- 7. 병원 방문 일정
appointments (
  id, user_id
  hospital_name   text
  department      text null   -- "내과" 등
  visit_at        timestamptz
  remind_before   text null check in ('none','day_before','same_day')
  memo            text null
  source, created_at, updated_at
)

-- 8. 진료 시 질문 메모
appointment_questions (
  id, user_id
  appointment_id  uuid FK → appointments (cascade)
  content         text (최대 200자)
  is_done         boolean default false
  sort_order      int
  created_at, updated_at
)

-- 9. 가족 초대 코드
family_invites (
  id, owner_id
  code_hash       text      -- 6자리 코드는 해시로만 저장
  relation_label  text      -- "딸"
  share_bp, share_glucose, share_weight, share_intakes, share_appointments  boolean
  expires_at      timestamptz  -- 생성 후 24시간
  used_at         timestamptz null
  failed_attempts int default 0  -- 5회 실패 시 폐기 (무작위 대입 방지)
  created_at
)

-- 10. 가족 연결 (공유 항목별 권한 = 가족별 권한 관리)
family_links (
  id
  owner_id        uuid FK   -- 정보 주인 (공유하는 사람)
  viewer_id       uuid FK   -- 보는 가족
  relation_label  text
  share_bp, share_glucose, share_weight, share_intakes, share_appointments  boolean
  status          text check in ('active','revoked')
  consented_at    timestamptz    -- 제3자 제공 동의 시각
  consent_version text
  revoked_at      timestamptz null
  revoked_by      uuid null      -- 주인 철회 / 가족 스스로 해제 모두 가능
  created_at, updated_at
  UNIQUE (owner_id, viewer_id) where status = 'active'
)
-- 가족 권한은 "보기"만. 가족이 기록을 대신 입력·수정하는 기능은 1차 범위 밖.

-- 11. 긴급 연락처
emergency_contacts (
  id, user_id
  name            text
  phone           text
  relation_label  text null
  priority        smallint   -- 1이 가장 먼저 표시
  created_at, updated_at
)

-- 12. 알림 설정 (실제 알림 예약은 기기 안에서. 서버에는 설정값만)
notification_settings (
  user_id         uuid PK
  meds_enabled            boolean default true
  appointments_enabled    boolean default true
  updated_at
)

-- 13. 보안 감사 기록
audit_logs (
  id              bigint PK (자동 증가)
  occurred_at     timestamptz default now()
  actor_id        uuid null   -- 행동한 사람
  subject_id      uuid null   -- 정보 주인
  action          text        -- 'insert','update','delete','family_view','consent_agree',
                              --  'consent_withdraw','link_create','link_revoke','account_delete','login'
  target_table    text null
  target_id       uuid null
  detail          jsonb null  -- 바뀐 컬럼 이름만. 건강 수치 자체는 넣지 않음
)
-- 사용자는 INSERT/UPDATE/DELETE 불가. 트리거·서버함수(security definer)만 기록.
-- 보관기간: 2년 [추정·전문가 검토: 안전성 확보조치 기준의 접속기록 보관 의무 확인 필요]
```

### D-3. 가족 공유 권한을 서버에서 검사하는 방식

```
가족 앱 ──▶ rpc('get_shared_summary', { owner_id })
                │
                ▼  (DB 함수 안에서, 앱을 믿지 않고 다시 검사)
           1) 호출한 사람 = family_links.viewer_id 인가?
           2) status = 'active' 인가?  (철회되었으면 즉시 빈 결과)
           3) 요청 항목의 share_xxx = true 인가?
           4) 통과한 항목만 반환 + audit_logs에 'family_view' 기록
```

- 기본 테이블에는 **가족용 RLS 정책을 만들지 않음** → 앱 코드가 실수해도 가족이 직접 테이블을 읽을 방법이 없음.
- 공유 범위도 최소화: 혈압·혈당은 "최근 7일 기록", 복약은 "오늘·최근 7일 확인 여부"만. 메모·질문 메모는 공유하지 않음.
