### 처방전·약봉투 사진 읽기 — 상세 (사용자 요청 2026-11-05)

**결정 (2026-11-06)**: 4단계 이후 후속 기능, **A 방식(휴대폰 안 글자 인식, 무료)**으로 진행. 정식 앱 빌드(TestFlight 준비)와 함께. 새 패키지는 그때 따로 승인.
먼저 만든 것: 약 등록 화면의 '약 봉투에 적힌 대로 고르기'(하루 몇 번 + 식사 전·후) — 사진 읽기 결과도 이 칸을 채우는 방식으로 연결 예정.

**흐름**: 사진 찍기 → 글자 읽기 → "이렇게 읽었어요" 확인 화면 → 사용자가 고치거나 확인한 뒤에만 저장 → 약 일정·알림·병원·약국 채움

**읽을 항목**
| 출처 | 항목 |
|---|---|
| 처방전 | 병원 이름, 처방일, 약 이름, 1회 양, 하루 횟수, 며칠분 |
| 약봉투 | 약국 이름·전화, 조제일, 약 이름, 먹는 때(아침·점심·저녁·자기 전, 식전·식후), 며칠분 |

**같은 날 처방전 + 약봉투 → 하나로 합치기** (사용자 요청)
- 같은 묶음으로 보는 조건: 처방일과 조제일이 **같은 날**(또는 조제일이 처방일 다음 날까지) **그리고** 약 이름이 절반 이상 겹침
- 약 이름 비교: 빈칸·괄호·함량 표기(mg 등)를 빼고 비교 (예: "아모디핀정 5mg" = "아모디핀정")
- 합칠 때 역할: 병원은 처방전에서, 약국·먹는 때는 약봉투에서, 며칠분은 둘이 같을 때만 자동 (다르면 확인 화면에서 고르게 함)
- 두 사진의 내용이 서로 다르면 자동으로 정하지 않고 **둘 다 보여 주고 사용자가 고름**
- 이미 등록된 같은 약이 있으면 새로 만들지 않고 "이미 등록된 약이에요" 안내 → 그대로 두기 / 일정 바꾸기 중 고름
- 같은 사진을 두 번 찍어도 한 번만 반영

**안전·개인정보 원칙**
- ⚕ 자동 저장 없음. 앱은 옮겨 적기만 하고 복용법을 판단·변경하지 않음
- 🔒 질병 분류 코드·주민번호·의사 이름은 읽더라도 저장하지 않음. 사진은 읽은 뒤 바로 지움
- 🔒 외부 서버로 사진을 보내는 방식이면 민감정보 제3자 제공·국외 이전 동의와 전문가 검토 필요

**방식 후보**: A 휴대폰 안 글자 인식(무료, 정식 빌드 필요, 추천) / B 네이버 CLOVA OCR(유료) / C AI 읽기·정리(유료, 국외)
